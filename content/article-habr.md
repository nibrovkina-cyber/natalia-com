## TL;DR

Разделила маркетинг малого бизнеса на 16 функциональных ролей. Каждой написала отдельный системный промпт с методологией. Сверху положила пять «фундаментов» (Огилви, Шварц, Хопкинс, голос бренда, измерения), которые подгружаются под все запросы. Получилось **21 SKILL.md** в одном репозитории под MIT-лицензией. Общая память — единый файл `brand-memory.json`, который читают все промпты. Тестировала на демо-сайте небольшой клиники, время прогона — 60 секунд. Pre-revenue, build-in-public, ссылка на GitHub в конце.

---

## Зачем это нужно

Стандартный запрос «веди себя как маркетолог» в ChatGPT не работает. Точнее, работает плохо. У него три фундаментальные проблемы:

**1. Нет общей памяти между задачами.** Каждый чат начинается с нуля. Объясняешь кто я, что продаю, кому продаю, какой тон использую — и так пятнадцать раз в день, под каждую задачу.

**2. Один универсал не выигрывает у пятнадцати специалистов.** Заголовок, лендинг, рекламный текст, лид-магнит, email-серия, SMM-пост, аналитика — это разные навыки и разная методология. Универсальный промпт усредняет всё до «общих слов с положительной коннотацией».

**3. Нет объяснимости.** Когда AI что-то предлагает, ты не знаешь, почему. Это не позволяет учиться и не позволяет аргументировать клиенту, почему именно такой заголовок.

Я начала собирать своё решение для собственных нужд. Когда поняла, что архитектура работает не только для меня, выложила всё в публичный репозиторий под MIT.

**21 SKILL.md** = 16 функциональных агентов + 5 фундаментов.

Каждый файл — отдельный markdown с YAML-фронтматтером:

```markdown
---
name: landing-cro
description: Audits and rewrites landing pages by Ogilvy principles
inputs:
  - url или html того, что нужно переписать
  - brand-memory.json (контекст бизнеса)
outputs:
  - переписанная страница
  - блок "почему так" с цитатами методологии
foundations: [ogilvy, hopkins, brand-voice]
---

# Системный промпт landing-cro

[3-5 тысяч знаков системного промпта с правилами, чек-листами,
примерами хороших и плохих вариантов]
```

Поле `foundations` — список фундаментов, которые подгружаются автоматически перед основным промптом. Это позволяет не дублировать правила Огилви в каждом из 16 агентов и обновлять методологию централизованно.

## Brand Memory

Главная штука, которая делает это **командой**, а не пятнадцатью отдельными чатами — это `brand-memory.json`. Один файл с контекстом бизнеса:

```json
{
  "brand": {
    "name": "Клиника Дента",
    "founded": 2018,
    "city": "Москва",
    "websites": ["клиника-дента.рф"]
  },
  "audience": {
    "primary": "родители детей 4-12 лет в районах ЮЗАО",
    "awareness_level": "problem_aware",
    "objections": ["страх перед стоматологом", "цена", "недоверие к специалистам"]
  },
  "positioning": {
    "category": "детская стоматология",
    "differentiation": "приём ведут только сертифицированные детские ортодонты",
    "proof_points": ["{количество} лет опыта", "{количество} приёмов в год"]
  },
  "voice": {
    "tone": "тёплый, без сюсюканья, профессиональный",
    "forbidden_words": ["лучший", "уникальный", "качественный", "индивидуальный подход"],
    "preferred_phrases": ["приём без стресса", "пошагово", "понятно ребёнку"]
  },
  "constraints": {
    "legal": ["152-ФЗ для PII", "закон о рекламе медуслуг"],
    "platform": ["Яндекс Директ для медицины — спец-требования", "ERID для всей рекламы"]
  }
}
```

Все 16 функциональных агентов читают этот файл первым. Это даёт согласованность голоса между лендингом, рекламой, SMM, email-цепочкой и кейсом, написанным разными агентами.

Поле `forbidden_words` — отдельная штука, которая решает 80% проблем малого бизнеса в России: убирает «качественный», «лучший», «индивидуальный подход» и прочие слова-пустышки автоматически, на уровне системного промпта. Любой агент, попытавшийся это написать, получит отказ от валидатора и переформулирует.

## Фрагмент промпта foundation/ogilvy.md

Чтобы было понятно, как это устроено внутри:

```markdown
---
name: ogilvy
description: Foundation rule-set for headlines, body copy, structure
type: foundation
---

# Foundation: Ogilvy

Применяется к любой задаче, где есть текст, который читает человек.

## Правила, которые проверяются

1. **Заголовок — 80% работы**
   Заголовок читают в 5 раз больше людей, чем тело текста. Если заголовок
   слабый, текст можно не писать.

2. **Назови аудиторию прямо**
   ❌ "Услуги в области маркетинга"
   ✅ "Для владельцев небольших стоматологий до 5 кресел"

3. **Не продавай продукт — продавай его эффект для клиента**
   ❌ "Профессиональная имплантация"
   ✅ "Жуёте обычную еду через 3 дня после приёма"

4. **Никаких общих слов**
   Слова `качественный`, `лучший`, `профессиональный`, `индивидуальный`,
   `уникальный` — запрещены без исключений.

5. **Заголовок как фильтр**
   Хороший заголовок отсекает нерелевантную аудиторию. Не пытайся
   нравиться всем — пытайся резко цеплять своих.

## Чеклист самопроверки (применяется автоматически перед выдачей)

- [ ] В заголовке названа конкретная аудитория?
- [ ] В заголовке есть проверяемое число или конкретный результат?
- [ ] В заголовке нет ни одного слова из forbidden_words из brand-memory?
- [ ] Тело текста развивает обещание заголовка, а не пересказывает его?

Если хотя бы один пункт не выполнен — переформулируй и повтори
самопроверку. Не выдавай результат, пока все 4 пункта не выполнены.
```

Фундамент `hopkins.md` устроен так же, но работает с другим срезом — проверкой каждого утверждения на доказуемость. Любой claim проходит через жёсткий фильтр: «можно ли это измерить, сослаться на источник или показать процесс?». Если нет — claim вылетает или переформулируется в «{плейсхолдер для проверяемого факта}».

`schwartz.md` — это не правила, а классификатор. Он определяет уровень осведомлённости аудитории по `brand-memory.json` и навязывает соответствующую структуру тексту. Уровень 1 (unaware) — большой story-driven заход. Уровень 5 (most aware) — короткое предложение по цене. Между ними три промежуточных типа структур.

## Что внутри агента (на примере landing-cro)

```markdown
---
name: landing-cro
description: Audits and rewrites landing pages
foundations: [ogilvy, hopkins, brand-voice, measurement]
---

# Системный промпт landing-cro

## Вход

URL сайта или HTML-блок. Из brand-memory.json берётся всё остальное.

## Что делаешь по шагам

1. **Аудит структуры.** Перечисли блоки страницы сверху вниз.
   Под каждым блоком — что он должен делать (по Огилви) и что он
   делает фактически.

2. **Найди шум.** Подсвети все слова из `voice.forbidden_words` и
   все недоказуемые claims. Покажи их как diff.

3. **Определи уровень awareness.** По описанию ЦА из brand-memory
   определи, на каком уровне Шварца находится посетитель в момент
   входа на страницу. Обоснуй.

4. **Перепиши блоки в правильном порядке** под этот уровень awareness.
   Под каждым переписанным блоком — короткое объяснение «по какой
   методологии и почему».

5. **Финальный CTA.** Конкретный глагол + выгода + срок или ограничение.
   Без слов «оставить заявку», «связаться с нами».

6. **Самопроверка.** Прогон через чеклисты Ogilvy и Hopkins.
   Если хотя бы один пункт не пройден — итерируй заново.

## Выход

Возвращаешь два блока:

### Блок A: переписанная страница
Чистый HTML или Markdown, готовый к публикации.

### Блок B: «почему так»
Короткие объяснения по методологии. По 2-3 строки на каждый блок.
Назначение — чтобы человек понимал решения и мог их защитить
перед заказчиком.
```

Размер промпта — около 4 000 знаков. С подгруженными фундаментами получается ~15-18 тысяч знаков системного контекста. По меркам современных моделей (Claude Sonnet 4.6 с 200K контекстом) — это незначительная нагрузка.

## Стек

- **Модель**: Claude Sonnet 4.6 (через Anthropic API). Её сильная сторона — следование длинным сложным инструкциям и устойчивая работа со структурированным выводом.
- **Хостинг UI**: Next.js 16 + Vercel. Один репозиторий — `natalia.com` для UI и waitlist, второй — `natalia-marketing-department` для всех 21 SKILL.md под MIT.
- **Brand Memory**: на старте — JSON-файл, который пользователь редактирует через UI. План на v2 — Postgres + миграция в multi-tenant.
- **Безопасность**: SHA-256 для PII в логах, CSP/HSTS/X-Frame-Options через `vercel.json`, rate-limit через Vercel KV.

Локально можно поднять без Vercel. Достаточно `claude` CLI + `claude-code` агента, который умеет читать SKILL.md из файлов. Команда `claude --skill agents/landing-cro.md` запускает конкретного агента с автоподгрузкой указанных в YAML фундаментов.

## Открытые вопросы (приглашаю в обсуждение)

Эта система — рабочая, но я не считаю её финальной. Открытые вопросы, по которым буду благодарна за критику и эксперименты в issues:

**1. Brand Memory: JSON или Postgres с самого начала?**
JSON хорош для open-source — клонируется и редактируется вручную. Но при росте числа клиентов мне всё равно придётся переезжать на DB с RLS. Стоит ли стартовать с DB сразу, или это преждевременная оптимизация? Сейчас выбрала JSON, готова обсуждать.

**2. Эвалюация промптов.**
Сейчас тестирую вручную: прогоняю набор «эталонных» сайтов через каждого агента, смотрю выход. Хочется автоматизированных evals по типу OpenAI/Anthropic, но в маркетинге метрика «хороший копирайт» не сводится к exact match. Думаю в сторону LLM-as-judge с эталонной выборкой из 50 примеров на каждого агента.

**3. Локализация.**
Сейчас фундаменты — двуязычные (RU + EN), агенты — RU-first с EN-копиями. Стоит ли разделить ветки `ru/` и `en/` явно или оставить один файл с двумя секциями? Склоняюсь к одному файлу с двумя секциями — чтобы поддерживать единую логику, но не уверена.

**4. Multi-tenancy.**
Open-source версия — single-tenant (один `brand-memory.json` на инстанс). SaaS-версия требует tenant_id во всех записях. Опыт работы с multi-tenant архитектурой на Next.js + Postgres — приветствуется в комментах.

## Бизнес-модель и почему open-source

Полный честный ответ: я pre-revenue. Нет ни одного оплачивающего клиента. Если бы я закрыла эту работу под платной стеной и продавала через хайп — никто бы не пришёл (4 подписчика на YouTube на момент публикации).

Поэтому делаю обратное. Выкладываю всё бесплатно. Воронка такая же, как у Vercel поверх Next.js, как у Supabase поверх Postgres, как у PostHog поверх ClickHouse:

1. **Free / GitHub** — все 21 SKILL.md под MIT. Можно склонировать, форкнуть, запустить локально, переписать.
2. **Self-Serve** — 2 990 ₽/мес — веб-инструмент с готовым UI и подключёнными ключами. Для тех, кому не хочется поднимать локально.
3. **Personal Audit** — 49 000 ₽ разово — я лично разбираю ваш сайт + 2 недели сопровождения.

Старая «open core» модель, перенесённая в маркетинг.
